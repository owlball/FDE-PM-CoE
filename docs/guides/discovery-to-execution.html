Phase 05 · W6

Discovery → Execution Handoff

A Go decision does not start Execute automatically. W6 is a discrete handoff phase — here is exactly what must be done, by whom, and in what order.

The rule: Execute cannot start until the Execute team has everything they need to run Sprint 0 without asking Discovery for clarification.

What "Go" actually means

A Go decision at the W5 Scorecard meeting means four things are true:

  • All four Go/No-Go criteria pass
  • The customer sponsor has aligned internally and confirmed their Go — including functional and technical readiness
  • All open items have named owners and deadlines

The three W6 activities

Define scope for Execute — Discovery PM

A 90-minute session with the customer POC and sponsor covering four dimensions: organisational reach, functional surface, data and systems, and outcomes and guardrails. The out-of-scope lane is filled in the same session — anything not in the scope statement is out of scope for Execute. This is the document that prevents scope creep in Sprint 3.

Name the Execute team — Discovery Lead

The Execute team joins in the final week of Discovery — not after W6 closes. Both SAP and customer sides must be named before W6 ends. The Discovery Lead stays engaged until the first Execute session is running without them — a one-week overlap is the minimum.

Build the Execute plan — Discovery Lead

A 90-minute planning session producing milestones to GA, review gates, steering cadence, operating model, and every environment named against the date it is needed with owner and deadline. Buffer gaps are deliberate — do not compress them.

The handoff package

The Execute team receives a complete package. Every item must be present and final — not "in progress" or "to be updated in Sprint 1":

ArtefactStatus requiredOwner
Standard specs Executive-signed · all Sprint 0 TBDs resolved or named with dates FDE PM + Engineer
Logic diagram Final · reviewed by Engineer FDE PM
User Journey Final · confirmed by Functional Experts FDE PM
UX state diagram Final · confirmed by Functional Experts FDE PM
UI SPA Final · confirmed by Functional Experts FDE PM
Prototype Disposition declared: reference only, baseline to extend, or discard FDE PM + Engineer

What Execute starts with

The Execute team's first action is a Sprint 0 planning session. They need to be able to run it without asking the Discovery team anything. That means:

  • The Agent Logic section of the spec has no unresolved TBDs — or every TBD has a named owner and date
  • Every data source has been confirmed reachable and whitelisted
  • The customer's technical and functional owners are available and have committed time
  • Non-production environments are available or a mock/sandbox start is agreed

Common handoff failure modes

FailureSymptom in ExecutePrevention
Spec handed over with open agent logic TBDs Sprint 0 planning stalls; Engineer has no basis for story points Every agent logic TBD resolved or has a named owner + date before Execution starts
Connectivity not confirmed Sprint 1 blocked waiting for connectivity approvals Start connectivity whitelisting in W1; track at every check-in
Execution PM not involved in W6 Execution PM starts cold — no context on decisions, open items, or client dynamics from Discovery Execution PM joins the final week of Discovery
Out-of-scope lane left blank Scope creep — customer adds features in Sprint 3 citing "we discussed this in Discovery" Fill out-of-scope lane explicitly in the same 90-min session as the in-scope lane
