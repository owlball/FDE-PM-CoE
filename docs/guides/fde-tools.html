    AI-Assisted Workflows

    FDE Tools Reference

    Ready-to-use AI workflows for every common Discovery task. Each prompt is in FDE Tools/reusable_prompts.md — paste it into Claude Code with your file paths filled in.

    Setup required: These tools run in Claude Code with the SAP MCP Suite installed. Follow the PMSkills setup guide to get Claude Code and the MCP servers running on your machine first.

    All FDE work runs from two locations on your machine: the FDE Tools folder (OneDrive - SAP SE/FDE Tools/) holds the shared kit — prompt library, spec template, build scripts, brand assets, and TTS/caption tools. Your per-engagement folders (OneDrive - SAP SE/Discovery/ and Execution/) hold everything project-specific. Use Prompt 2 to scaffold a new Discovery engagement folder; it copies the .mcp.json config that connects Claude to the SAP MCP tools (Jira, Teams, Outlook, Wiki, GitHub). Markdown spec files can be committed to GitHub; generated files in claude_output/ should not.

    SAP MCP Suite — installation

    What is the MCP Suite?

    MCP (Model Context Protocol) is what connects Claude to the tools and systems you work with every day. Without it, Claude can only work with files and text you paste into the conversation. With it, Claude can read and write to Jira, send Teams messages, search your Outlook, browse the web, and more — directly from the conversation, without you switching between applications.

    The SAP MCP Suite installs 7 servers, each connecting Claude to a different system:

    ServerWhat it lets Claude do
    github-toolsRead and write to GitHub repositories — useful for storing and retrieving specs, templates, and engagement documents
    playwrightControl a browser on your behalf — extract data from web pages, capture content from SAP web interfaces, or automate repetitive browser tasks
    sap-auth-mcpHandle SAP authentication so the other servers can connect securely
    sap-jiraRead and create Jira tickets, search the backlog, update story status
    sap-msteamsSearch Teams messages, post updates, find contacts
    sap-outlookSearch and read emails, find meeting information
    sap-wikiSearch and read SAP internal wiki pages

    The MCP suite connects Claude Code to Jira, Teams, Outlook, Wiki, and GitHub inside SAP. Full video walkthrough: Watch setup video →

    The onboarding repo is at github.tools.sap/app-AI-FDE/onboarding.

    Steps:

    1. Copy the repo README and paste it into Claude Code
    2. Ask Claude to clone the repo — paste the GitHub URL so it knows which repo
    3. After a while Claude will ask you to open a new terminal and paste a block of code — do that
    4. The new terminal will prompt for three values — find these in the chat interface instructions:
      • SAP_DOMAIN_MODELS_IAS_TENANT — the URL
      • SAP_DOMAIN_MODELS_IAS_CLIENT_ID — the client ID
      • SAP_DOMAIN_MODELS_IAS_CLIENT_SECRET — the client secret
    5. Go back to the Claude Code instance and tell it you are done and to check the installation
    6. Claude will prompt you to exit and reopen Claude Code — do that and you are ready

    Gotcha: If Claude tells you to remove https:// from the URL when entering the IAS tenant value, ignore that instruction. Enter the full URL including https://.

    What you get — 7 MCP servers:

    ServerTools
    github-tools14 tools
    playwright22 tools
    sap-auth-mcp4 tools
    sap-jira44 tools

    Project Setup (Prompt 2)

    When to use: First thing when a new engagement is confirmed — before any spec work or meetings begin. Run it once per client.

    What it does: Creates the full standard folder tree under Discovery/[CLIENT NAME]/ — spec folders, Demo, Diagrams, Meetings, From Client, claude_output, and tools. Consistent structure means every PM and engineer on the team knows exactly where to look.

    How to trigger: Open Claude Code in your Discovery/ root folder, paste Prompt 2, and replace [CLIENT NAME] with the engagement name. Done in under 10 seconds.

    Common mistake: Running it inside an existing client folder instead of the Discovery/ root — the paths end up nested incorrectly.

    Spec Builder (Prompt 1)

    When to use: Use any time you need to produce or update the Word version of the spec.

    What it does: Reads your filled-in Markdown spec, applies SAP FDE Word styling (cover page, SAP logo, section headers, correct fonts and margins), and writes a .docx file into your spec folder. Matches the template exactly — no manual formatting needed.

    How to trigger: Open Claude Code in the engagement's Spec work/ folder, paste Prompt 1, and set the SPEC_MD path to your Markdown file. The output appears in the same folder.

    Tip: The Markdown file is your working document — Claude reads and writes MD natively, so keep all edits there. When you need to share the spec with stakeholders for review or comments, run the builder to generate the Word document. The Word doc is a snapshot for sharing, not the source of truth — always go back to the MD file for further edits.

    If you want version history on the spec, commit the MD file to GitHub. The generated Word doc doesn't need to be committed.

    Fiori UI Render (Prompt 6)

    When to use: Use whenever you need to show the customer what the future-state UI would look like — before you have a working POC, or to mock screens the POC doesn't yet cover.

    What it does: Generates a self-contained static HTML mockup styled with SAP Fiori Horizon design tokens — correct colours, typography, icon names, and layout patterns. Customers and engineers read it as a credible near-production UI, not a sketch.

    How to trigger: Describe the screen in plain English in Prompt 6 — list the key data fields, actions, and any navigation. Claude reads FDE Tools/Brand/fiori-horizon-design-tokens.css and outputs a single HTML file into Demo/.

    Tip: After the first render, iterate by describing specific changes ("move the filter panel to the left, add a status badge column") rather than re-running the full prompt. Claude will diff-edit the existing file.

    Meeting Recording → UI Reference (Prompt 3)

    When to use: After any customer demo or system walkthrough where they screenshared their existing tools. The goal is to capture the AS-IS UI so you can reference it in the spec and TO-BE flow.

    What it does: Extracts still frames from the Teams recording at regular intervals, runs parallel Claude agents over the images (each agent describes one screen), and assembles a structured Markdown reference doc with annotated screenshots and field inventories.

    How to trigger: Download the Teams recording MP4, put it in the session's Meetings/[YYYY-MM-DD]/ folder, then run Prompt 3 pointing at the file. Outputs a _UI_reference.md file alongside it.

    Tip: Run this within a day of the meeting — the reference doc is most useful when you can cross-check it with your own memory of the session.

    Cost warning: This prompt runs multiple agents in parallel and can consume a significant portion of your daily budget on longer recordings. Before running it on a full-length recording, tell Claude to process only the first 5 minutes first — check the cost before extending to the full clip.

    Teams Transcript Extractor (Prompts 7 & 8)

    First time using the browser console? When you paste a script for the first time, the browser will block it and show an error. Type allow pasting and press Enter, then paste the script again.

    When to use: After every customer call where you enabled transcription. Extract before the meeting expires in Teams (recordings are deleted after 60 days by default).

    Prompt 7 (recording-hosted transcript): Open the meeting in Teams, navigate to the transcript in SharePoint, open browser DevTools console, paste the Prompt 7 script. It scrapes the VTT/VTT content and copies a clean text file to your clipboard.

    Prompt 8 (chat Transcript tab): For meetings without a recording. Open Teams in a browser — you cannot access the developer console from the Teams desktop app. In the browser, open the meeting chat, click the Transcript tab, open DevTools (F12 or right-click → Inspect), go to the Console tab. Before pasting the script, click the context dropdown at the top of the Console tab (it shows "top") and select RecapxPlatIframe (xplatplugins.aspx) — the transcript lives inside an iframe and the script won't find it otherwise. Paste the Prompt 8 script and press Enter. Same output as Prompt 7.

    Save it immediately to Meetings/[YYYY-MM-DD]/[session]_transcript.txt. Raw transcripts are large — always run the Transcript Cleaner next before using them as Claude context.

    Transcript Cleaner (Prompt 9)

    When to use: Immediately after extracting any transcript. Always clean before passing a transcript to Claude as context — raw transcripts contain filler words, overlap artefacts, and speaker-ID noise that inflates token count without adding signal.

    What it does: Removes filler words, corrects obvious STT errors, merges run-on speaker turns, and strips non-content artefacts. Typically reduces transcript size by 20–70% while preserving every substantive statement.

    How to trigger: Run Prompt 9 from the Meetings/[YYYY-MM-DD]/ folder pointing at the raw transcript. Output is saved as [session]_transcript_clean.txt alongside the original.

    Tip: Cleaning transcripts saves credits, but the bigger benefit is context efficiency — a cleaned transcript is small enough that you can paste several meetings into a single conversation, giving Claude multi-meeting context without hitting the context window limit.

    Cross-File Sync (Prompt 4)

    When to use: Any time a spec change needs to propagate to multiple files — for example, renaming the use case, updating a KPI value, or revising the TO-BE process description after customer feedback.

    What it does: Runs a grep-first pass across your engagement folder to locate every file containing the affected content, then applies the change consistently across all of them — spec MD, HTML demo, diagrams that embed text, and any other files Claude finds.

    How to trigger: Open Claude Code at the engagement root, paste Prompt 4, describe the change in plain English ("the use case is now called X instead of Y"), and let Claude run the grep and propose edits before writing anything. Review the diff before confirming.

    Tip: Always describe the change semantically, not just as a text find-replace. Claude needs the context to handle edge cases — e.g. where the old name appears in a heading vs. a URL vs. a caption.

    Standard engagement folder structure

    Use Prompt 2 (Project Setup) to scaffold this automatically for each new client:

    Discovery/
└── [CLIENT NAME]/
    ├── Spec work/
    │   └── [CLIENT] spec/
    │       ├── MD versions/          ← Markdown spec files (commit to GitHub)
    │       └── [CLIENT]_Spec_v0.1.docx
    ├── Demo/                         ← HTML demo files
    ├── Diagrams/                     ← draw.io and SVG files
    ├── Meetings/
    │   └── [YYYY-MM-DD]/
    │       ├── [session]_transcript.txt
    │       ├── [session]_transcript_clean.txt
    │       └── [session]_UI_reference.md
    ├── From Client/                  ← client-provided materials
    ├── claude_output/                ← generated files (do not commit)
    └── tools/                       ← project-specific scripts
